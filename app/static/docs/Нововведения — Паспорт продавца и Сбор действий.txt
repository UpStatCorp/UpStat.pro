  1. ОДНА ТРЕНИРОВКА — ОДНА КРИТИЧНАЯ ОШИБКА
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ЧТО БЫЛО:
  После анализа звонка система давала менеджеру 5-6 тренировок сразу.
  Менеджер терялся, не знал за что хвататься.

ЧТО СТАЛО:
  Теперь после анализа создаётся ОДНА тренировка по САМОЙ КРИТИЧНОЙ ошибке.
  GPT сам решает, какая ошибка самая важная — та, исправление которой
  даст максимальный эффект на продажи.

КАК РАБОТАЕТ:
  1. Звонок анализируется как обычно
  2. GPT получает результаты анализа
  3. Из всех ошибок выбирает одну — самую критичную
  4. Определяет, к какому этапу продаж она относится (см. ниже)
  5. Создаётся одна тренировка, сразу доступная для прохождения

ЭТАПЫ ПРОДАЖ (5 штук):
  • contact      — Вступление в контакт и открытие
  • needs        — Работа с потребностями
  • presentation — Презентация
  • objections   — Работа с возражениями
  • closing      — Завершение сделки

ФАЙЛЫ:
  • app/services/training_plan_service.py — промпт и логика выбора ошибки
  • app/models.py — поле stage в модели Training

  2. ПАСПОРТ ПРОДАВЦА (SellerPassport)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ИДЕЯ:
  У каждого менеджера есть свой «паспорт» — профиль навыков.
  После каждого звонка GPT оценивает менеджера по 5 этапам продаж
  и записывает проценты в БД. Видно, как менеджер растёт со временем.

КАК РАБОТАЕТ (пошагово):

  Звонок №1 (первый звонок менеджера):
  ┌────────────────────────────┬────────┐
  │ Этап                       │ Оценка │
  ├────────────────────────────┼────────┤
  │ Вступление в контакт       │  4.0%  │
  │ Работа с потребностями     │  6.0%  │
  │ Презентация                │  3.5%  │
  │ Работа с возражениями      │  2.0%  │
  │ Завершение сделки          │  1.0%  │
  └────────────────────────────┴────────┘
  → Это базовая линия. Записывается в БД.
  → Самая критичная ошибка = «Завершение сделки» (1.0%)
  → Создаётся тренировка по закрытию

  Менеджер проходит тренировку по закрытию сделки.

  Звонок №2:
  ┌────────────────────────────┬────────┬────────┬────────┐
  │ Этап                       │ Было   │ Стало  │ Дельта │
  ├────────────────────────────┼────────┼────────┼────────┤
  │ Вступление в контакт       │  4.0%  │  4.0%  │   0    │
  │ Работа с потребностями     │  6.0%  │  6.5%  │ +0.5%  │
  │ Презентация                │  3.5%  │  4.0%  │ +0.5%  │
  │ Работа с возражениями      │  2.0%  │  2.0%  │   0    │
  │ Завершение сделки          │  1.0%  │  3.2%  │ +2.2%  │
  └────────────────────────────┴────────┴────────┴────────┘
  → Система видит: тренировка по закрытию → дельта +2.2% → ПРИМЕНИЛ
  → Записывается: training_applied = "yes", training_delta = +2.2
  → Теперь самая критичная ошибка = «Возражения» (2.0%)
  → Новая тренировка по возражениям

  И так по кругу: звонок → оценка → тренировка → звонок → сравнение.

КТО ТАКОЙ «МЕНЕДЖЕР»:
  • Если звонок загружен вручную — user_id того, кто загрузил
  • Если звонок из CRM — система берёт manager_name из CRM-записи,
    находит привязку в CRMManagerMapping и определяет user_id

ЧТО ХРАНИТСЯ В БД:

  Таблица seller_passports (одна запись на менеджера):
    • Текущие проценты по 5 этапам
    • Общий средний балл
    • Сколько звонков проанализировано
    • Сколько тренировок пройдено
    • Дата первого звонка

  Таблица passport_snapshots (одна запись на каждый звонок):
    • Проценты по 5 этапам на момент этого звонка
    • Какая тренировка была пройдена перед звонком
    • К какому этапу относилась тренировка
    • Применил ли менеджер тренировку (yes / no / partial)
    • Дельта по этапу (было → стало)
    • Комментарий GPT

GPT-ОЦЕНКА:
  GPT-4o-mini получает диалог + результаты анализа по чеклистам.
  Для каждого этапа даёт процент по шкале:
    0-4%   — этап полностью пропущен или грубо провален
    5-10%  — попытался, но с критическими ошибками
    11-25% — базовая работа, много упущений
    26-50% — средне, есть существенные зоны роста
    51-70% — хорошо, мелкие замечания
    71-85% — очень хорошо, незначительные улучшения
    86-100% — отлично, эталонная работа

  • app/services/seller_passport_service.py — вся логика (оценка, снимки, дельты)
  • app/models.py — модели SellerPassport, PassportSnapshot

  3. СБОР ДЕЙСТВИЙ МЕНЕДЖЕРОВ (ManagerActions)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ИДЕЯ:
  Система собирает конкретные фразы и приёмы менеджеров из каждого звонка.
  Определяет, привело действие к успеху (клиент приблизился к покупке)
  или к провалу (клиент отдалился). Когда набирается статистика —
  автоматически шлёт отчёт владельцу на почту.

  По сути: ИИ сам собирает «скрипт продаж» из реальных данных.

КАК РАБОТАЕТ (пошагово):

  Шаг 1 — Извлечение действий (после каждого звонка):
    GPT анализирует диалог и выделяет 2-6 ключевых действий менеджера.
    Для каждого определяет:
      • К какому этапу относится (contact / needs / presentation / objections / closing)
      • Что сказал/сделал менеджер (конкретная фраза или приём)
      • Тип: phrase (фраза), technique (приём), question (вопрос)
      • Результат: positive (клиент приблизился) или negative (отдалился)
      • Как отреагировал клиент

    Пример:
      Действие: "Предложил сравнительную таблицу с конкурентами"
      Этап: objections
      Тип: technique
      Результат: positive
      Реакция: "Клиент заинтересовался, попросил прислать"

      Действие: "Сразу назвал цену без объяснения ценности"
      Этап: closing
      Тип: phrase
      Результат: negative
      Реакция: "Клиент сказал 'дорого' и замолчал"

  Шаг 2 — Накопление (от всех менеджеров команды):
    Действия копятся в таблице manager_actions.
    Система ждёт минимум 10 звонков, прежде чем делать выводы.

  Шаг 3 — Агрегация и поиск паттернов:
    После каждого нового звонка система:
    1. Группирует похожие действия (по пересечению слов >= 60%)
    2. Считает: в скольких звонках встречается это действие
    3. Если действие есть в 60%+ звонков с одинаковым результатом
       → это ПАТТЕРН (не случайность)
    4. Паттерн помечается как «confirmed»

  Шаг 4 — Отчёт на почту владельцу:
    Когда появляются новые confirmed-паттерны, система автоматически
    отправляет красивое HTML-письмо владельцу команды:

    ┌──────────────────────────────────────────────────────────┐
    │  ✅ РАБОТАЕТ (успешные приёмы):                          │
    │                                                          │
    │  [Возражения] Предложение сравнительной таблицы — 75%    │
    │  [Открытие] Вопрос о текущем поставщике — 68%            │
    │                                                          │
    │  ❌ НЕ РАБОТАЕТ (вредные приёмы):                        │
    │                                                          │
    │  [Закрытие] Называть цену без объяснения ценности — 82%  │
    └──────────────────────────────────────────────────────────┘

СТАТУСЫ ПАТТЕРНОВ:
  • collecting — данных ещё мало, копим
  • confirmed  — набрано 60%+, это реальный паттерн
  • reported   — отчёт отправлен владельцу

ЧТО ХРАНИТСЯ В БД:

  Таблица manager_actions (каждое действие из каждого звонка):
    • team_id, user_id, conversation_id
    • stage — этап продаж
    • action_text — что сделал менеджер
    • action_type — phrase / technique / question
    • outcome — positive / negative
    • client_reaction — реакция клиента
    • confidence — уверенность GPT (0.0–1.0)

  Таблица action_patterns (агрегированные паттерны по команде):
    • team_id, stage, outcome
    • pattern_text — обобщённое описание действия
    • occurrence_count — сколько раз встречалось
    • total_calls — из скольких звонков
    • percentage — процент звонков с этим действием
    • status — collecting / confirmed / reported

ФАЙЛЫ:
  • app/services/manager_actions_service.py — вся логика
  • app/models.py — модели ManagerAction, ActionPattern
  • app/alembic/versions/013_add_manager_actions.py — миграция



  Раздел: AI-ВАЛИДАТОР ТРЕНИРОВКИ (TrainingValidatorService)

Он будет описывать:

Идея — после голосовой тренировки GPT проверяет транскрипт диалога и решает, зачесть тренировку или нет. Раньше score считался на клиенте эвристикой, теперь — AI.

Как работает — пошагово:

Менеджер завершает тренировку
Фронтенд собирает транскрипт и отправляет на сервер
Сервер отправляет транскрипт + данные тренировки (тема, рекомендация, этап, промпт) в GPT-4o-mini
GPT оценивает по 4 критериям (по 25 баллов каждый): полный цикл, понимание техники, качество исполнения, активное участие
Если score >= 70 → тренировка зачтена, следующая разблокирована
Если score < 70 → тренировка возвращается в статус available для повторной попытки
Что видит менеджер — красивый оверлей с результатом: score, прогресс-бары по критериям, обратная связь от AI

Персонализация промпта — Azure теперь получает не только общий SYSTEM_PROMPT, но и контекст конкретной тренировки (тема, проблема, рекомендация)

Файлы:

app/services/training_validator_service.py — сервис валидации
voice_assistant/router_new.py — эндпоинт /training/complete
voice_assistant/websocket_handler.py — персонализация промпта
app/static/js/voice-training.js — UI результата

  Файл: app/services/pipeline.py

  Цепочка обработки звонка:

  1.  Аудио → FFmpeg → WAV                        ← конвертация
  2.  WAV → ElevenLabs/Whisper → текст             ← транскрибация
  3.  Текст → JSON-диалог                          ← структурирование
  4.  JSON-диалог → чек-листы → GPT-4o            ← анализ по чеклистам
  5.  Все анализы → GPT-4o → итоговый отчёт       ← финальный анализ
  6.  Отчёт → сохранение файла                     ← запись результата
  7.  Win Probability (оценки чеклиста)             ← существовало ранее
  8.  Извлечение ошибок (TrainingErrorCorrection)   ← существовало ранее
  9.  Извлечение параметров (parameter_extraction)  ← существовало ранее
  10. ПАСПОРТ ПРОДАВЦА (seller_passport)            ← НОВОЕ
  11. СБОР ДЕЙСТВИЙ (manager_actions)               ← НОВОЕ
  12. Готово ✅

  Всё это встроено во все 3 пайплайна:
    • run_pipeline_from_text — текст из файла
    • run_pipeline_from_raw_text — текст из чата
    • run_pipeline — аудио

  4.1. AI-ВАЛИДАТОР ТРЕНИРОВКИ (TrainingValidatorService)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ИДЕЯ:
  После голосовой тренировки GPT проверяет транскрипт диалога между менеджером
  и ИИ-тренером. Оценивает выполнение задач тренировки и решает: зачесть или нет.
  Раньше score считался на клиенте эвристикой, теперь — AI.

КАК РАБОТАЕТ:
  1. Менеджер завершает тренировку (кнопка «Завершить»)
  2. Фронтенд собирает транскрипт диалога из чата
  3. Сервер отправляет транскрипт + данные тренировки в GPT-4o-mini
  4. GPT оценивает по 4 критериям (по 25 баллов каждый):
     • Полный цикл — прошёл и правильный, и неправильный вариант
     • Понимание техники — сделал верные выводы
     • Качество исполнения — правильные фразы/приёмы
     • Активное участие — не отписывался
  5. Если score >= 70 → тренировка зачтена, следующая разблокирована
  6. Если score < 70 → тренировка возвращается в available

ЧТО ВИДИТ МЕНЕДЖЕР:
  Красивый оверлей с результатом: score, прогресс-бары по критериям,
  обратная связь от AI, кнопка «Отлично!» или «Попробую ещё раз».

ПЕРСОНАЛИЗАЦИЯ ПРОМПТА:
  Azure теперь получает не только общий SYSTEM_PROMPT, но и контекст
  конкретной тренировки: тема, проблема, рекомендация, этап продаж.

  4.2. ЭКРАН ВЛАДЕЛЬЦА (Owner Command Center)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ИДЕЯ:
  Центр управления выручкой для владельца бизнеса.
  Показывает: где компания теряет деньги, почему, кто создаёт риск,
  что нужно сделать и какой возврат это даст.

6 РЕЖИМОВ:
  • Деньги — карта утечек выручки по параметрам звонков
  • Конверсия — что отличает успешные звонки от провальных
  • Риск плана — насколько pipeline реален
  • Скорость сделки — где сделки замедляются
  • Команда — рейтинг менеджеров по навыкам
  • Прогноз — «что если» (в разработке)
