## Выводы по файлу

1. **Три независимых механизма для одного сигнала «этап завершён»**: теги в тексте (937–950), tool-вызов через `function_call_arguments.done` (1040), tool-вызов через `output_item.done` (1064). 2. **Три разных подхода к «дождаться применения session.update» в одном файле**: событие `session.updated` с таймаутом 1.5 с (101–122), слепой `sleep(0.3)` (226), слепой `sleep(0.4)` (1294). Комментарий на 102 объясняет, почему слепые паузы плохи — и рядом живут две из них.
3. **Два блока полностью мёртвого кода**: 402–415 (14 строк после `return` плюс второй `except Exception`) и 839–844 (`try: pass`). Оба — следы правок, которые не довели до конца.
4. **Смена роли ИИ между этапами лечится тремя слоями сразу**: перезапись `session_instructions`, отдельный system-item «ЗАБУДЬ предыдущую роль», и полный промпт этапа внутри `response.instructions`. При этом сама роль определяется подстрокой `"клиент" in role_lower`.

## Выводы по файлу

1. **`_sync_status` как модульный словарь — самая заметная поломка.** При четырёх uvicorn-воркерах и nginx без sticky-сессий опрос статуса попадает в чужой процесс. Лечится переносом в Redis, который уже есть в проекте.
2. **Синхронизация идёт мимо arq**, хотя анализ уважает `use_queue()`. Многочасовой полный синк живёт в `BackgroundTasks` веб-процесса и умирает при любом деплое.
3. **Детект «HTML вместо аудио» дублируется на двух уровнях** — по `Content-Type` в `crm_service.py` (только OAuth-класс) и по первым 15 байтам здесь (обе ветки).
4. **`is_stuck` (613) не работает как задумано**: `created_at` — время синхронизации записи, а не начала анализа.
5. **Нормализация домена Bitrix строковыми `replace` в трёх местах** знает про 2 зоны, тогда как SSRF-фильтр — про 12.

## Выводы по файлу

1. **`elif` между аудио / текстом / изображениями (436, 471, 506) при том, что лимит считается суммой (397–399)** — пользователю списывают анализы за файлы, которые никогда не будут обработаны. Самое дорогое место файла.
2. **`limit(400)` с сортировкой по возрастанию (142)** отдаёт первые 400 сообщений вместо последних; та же строка скопирована в `chat_trener.py:104`.
3. **Диалог опознаётся по строке `"Мой диалог"` в пяти местах** — вместо флага в модели. `order_by(id.desc()).first()` признаёт, что дубликаты уже есть.
4. **Один `try/except` на 400 строк** плюс `if 'conv' in locals()` — сбой любой стадии выглядит одинаково и для пользователя, и в логах.
5. **`asyncio.create_task` без удержания ссылки** в фолбэке без очереди — задача может исчезнуть до завершения.
6. **Разные правила доступа у `/attachments/{id}` и `/chat/export/by-report/{id}`** к одним и тем же файлам.
